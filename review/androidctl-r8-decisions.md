## 一、方向和约定

1. **不现在合入。** 先做一批封闭的改动再合入，包括设备端。用户接受这一批"封闭但不小"。时间充足，实施方的成本不是约束。
2. **实施方可以自主做多轮打磨。** 什么时候交回由实施方自己判断。合入由用户最后拍板，不设合入规则。
3. **范围**只有两类：第二、三节的封闭清单；新任务里由工具自己造成的失败（每条要附那次真实记录）。其余新发现只记录。
4. **用户选定的做法是起点。** 实施方可以按实测偏离，但每处偏离单独一个提交，写明改前改后和依据，交回时列成清单由用户追认。
5. **过程。** 取消：小项表、"不能写不做"、实施方的三份累计评审、逐项处置表。保留：每次改动前跑全部测试，Linux 也跑。
6. **三条护栏。**
   - 首行按准入规则（第二节第 7 条），不为评审或统计加输出。
   - 指引只改已有句子；新增句子要附真实记录。
   - 每轮记一次净增行数，交回时一起报。
7. **交回之后评审方不评审，用户自己评。** 发布前要不要做完整评审，到发布时再定。

   - 写明打开网址用 `open --url`。
   - 删掉指向显示专题的两句（`SKILL.md:33`、`:128`）。
   - "已知步骤可以连发"（`SKILL.md:39`）改成"同一批里某条命令退出码不是 0 就停下后面的"。

4. **独立 docs 仓库维持。** 取消 150 KB 上限。行为改动照常同步，但只改已有句子，不为每条改动新增段落。真机清单里"是发布条件，不是合入条件"那句按第六节第 3 条改掉，只改这一句。

**"结果未知"一节的英文初稿**（评审方起草，供实施方迭代）：

```markdown
### UNKNOWN

The action may or may not have taken effect. After the original CLI process ends:

1. Read the tree returned with this result. If it is missing or still changing,
   take one read-only `snapshot`.
2. If it shows the state you asked for, treat the change as done. Continue.
3. If the result names a next step (for example `ime REF` on the field that now
   holds your text), do that step.
4. Otherwise confirm read-only that nothing happened and the operation has ended
   ([checks](reference.md#unknown-and-resource-release), not elapsed time), then
   repeat the same command once. If it is UNKNOWN again, stop and report. Do not
   try the same change through another input method.
5. Never repeat an irreversible action such as a payment, a send or a deletion.
   Rely on an authoritative record or the object's clear state.
```

## 五、验证

1. **回归**：固定四题各跑 1 次，不再和基线比成本。
2. **针对性运行**各 1 次：主题切换题、一道网页题的入口、那张长网页。
3. **新任务**：这一批就出一批（约 10 道，各 1 次，不设通过线）；并重跑上次没过的 Files、文章日期、主题切换三题，前两题先修题面。
4. **新题规格**：出题前在设备上把验收点走一遍；评测外壳传递真实退出码；失败按工具、指引、App、站点、题面分类；判定标准加一条"答复里不能有命令输出以外的事实"（问-3，用户选 B）。第一批新题的题面和验收点由评审方先审一次，之后实施方自主。
5. **观察时间的试验**：只在界面上有加载指示时把动作后的观察延长到 3 秒，网页题和路线题各跑 1 次。排在其他改动都做完、验证完之后，对着最终代码做。试验代码不进这一批，结果交回时用户定。"点链接后带回旧页面"（缺-2）和那约 100 行补全规则（`UiPostAction.kt:341-447`）等这个试验的结果再定。
6. **Files 点击方式的对照**（取-15）：同一状态下无障碍点击和触摸各 3 次，由实施方在模拟器上做。

## 八、评审方补的理解

**过程**

2. **"每次改动前跑全部测试，Linux 也跑"**指每个提交之前（包括每处偏离的单独提交）跑一次主机端全部测试（Windows 和 Linux 各一次）和设备端全部测试；首次失败照旧如实保留。

## 十、实施方动手前要知道的

这些来自写这份文件时的源码核对，逐条的依据在 `sub-reports/137-source-check.md`。

1. **取-1 的事实只能附加，不能改结论。** 核对的结论在动作后的观察之前就定了，新界面树在观察之后才有。重建后窗口编号、节点编号和引用都会变，"同一位置、同一编号"要用位置、资源编号、角色、所在行的标签和所属的包来对。删统计字段时不要连带删掉"根节点读不到之后再读一次"的那段（`UiPostAction.kt:156-170`），取-1 的新界面树靠它才拿得到。
