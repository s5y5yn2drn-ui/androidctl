# 从这里开始

这是对 AndroidCtl 改进路线的评审材料。评审方只评审，不实施，不改提交历史。

评审到现在共七轮。前三轮评的是调研候选（产品 `3f45af6`，基线 `7d5be70`）和实施方的研究与建议；第四轮评的是实施方在其上继续做出的整轮候选（产品 `4235af9`，独立 docs `9b8c5bd`）；第五轮评的是实施方按第四轮决定继续做出的候选（产品 `cab84b8`，独立 docs `31bae00`）；第六轮评的是实施方按第五轮裁决做完、认为可以交付的完整候选（产品 `fb75afc`，独立 docs `66bb380a`）；第七轮评的是实施方按第六轮裁决做完那一批改动和实测之后的候选（产品 `f401deb`，独立 docs `dfe5e45`）。

**当前状态：用户已对第七轮评审作出决定，记录在 `androidctl-r7-decisions.md`。决定是不合入，再做一轮同样形式的打磨：评审报告"进下一轮"的 23 条全做，另加小项和维护性删减，做完后做第八轮完整评审。决定文件第七节原有的 13 个问题用户已经全部答复，42 条读法已经全部确认，都已写回各节；现在没有等用户回答才能动手的部分。写回答复时评审方又补了 5 条读法（读-43 到读-47），等用户确认，确认之前实施方按读法做。实施方遇到问题先自主推进，不中途问用户，留到交付时一起问（决定文件第二节第 8 条）。**

## 以谁为准

1. 用户的明确指示。
2. `androidctl-r7-decisions.md` 里的决定。其中第三节是评审方代定、用户可改的（第 4 条用户已改定）；第七节的 13 问用户已经答复，读-1 到读-42 已经确认，读-43 到读-47 在用户确认之前是评审方的理解。
3. `androidctl-r6-decisions.md` 里没有被上一条改动的决定。
4. `androidctl-r5-decisions.md` 里没有被前两条改动的决定。
5. `androidctl-r4-decisions.md` 里没有被前三条改动的决定。
6. 第三轮评审里用户确认过、又没有被前四条改动的授权范围、已决定事项和默认做法。
7. 第七轮评审的正文。其中评审方的推荐与用户的裁决不同的地方，以裁决为准：合入与否、要不要第八轮、删减放在什么时候、基线重跑、实施方的累计评审、下-10 何时改、推到临时分支跑自动检查（不做）。`--all` 的范围，用户起初定得比报告窄，重议后与报告推荐的相同。
8. 第六轮评审的正文。其中评审方的推荐与用户的裁决不同的地方，以裁决为准：第 1、5、7、8 题；"冻结"的提法；A3 的修法；第二组"合入后再定"；§8 的顺序；附录一"合入后顺手做"；附录一里 `session open` 默认主屏那一条（报告只说"可以考虑"，评审方在随后的问答里推荐不做，用户选了做）。
9. 第五轮评审的正文。其中评审方的推荐与用户的裁决不同的地方（第 4、8、16 题），以裁决为准。
10. 第四轮评审的正文。
11. 前两轮定稿。
12. 工作记录。

工作记录写于不同时点，彼此之间、以及与各份报告之间有不一致。最容易带偏的说法列在各份报告的附录里。

## 给实施者

- 要做什么、边界在哪，按 `androidctl-r7-decisions.md`；它没有改动的部分按 `androidctl-r6-decisions.md`，再按第五轮、第四轮的决定文件。这一批的清单和先后依赖在第七轮决定文件第五节；先读它第六节的风险提示再动手。第七节的问题用户已经答复，没有要等的部分；遇到问题先自主推进，不中途问用户（第二节第 8 条）。
- 决定文件写明"由实施方定"的条目由实施方定。遇到问题先自主推进，不中途问用户。四块之内按第 21 项直接删或降级，记录里写明；四块之外有能力损失的取舍，先按不损失能力、最容易撤回的做法做完，记录里单列，交付时一起问（决定文件第二节第 8 条）。
- 第五轮评审 §4 的发现可以直接核对，每条的去向见第五轮决定文件第三节。第四轮缺陷清单的现状见第五轮评审 §6。
