# 从这里开始

这是对 AndroidCtl 改进路线的评审材料。评审对象是调研候选（产品 `3f45af6`，基线 `7d5be70`；独立 docs `e91212e`）和实施方三轮的研究、建议与模拟器实测。

评审只提方案，不实施，不改提交历史。评审的推荐不构成用户批准；是否实施、按什么范围实施，由用户决定。

## 这里有什么

| 文件 | 作用 |
| --- | --- |

| `sub-reports/01` … `34` | 评审过程的工作记录，只在需要追溯细节时查阅 |

## 以谁为准

1. 用户的明确指示。
2. 第三轮评审。
3. 上一版评审定稿（与第三轮评审不一致处，以第三轮评审为准）。
4. 工作记录。

工作记录写于不同时点，彼此之间、以及与两份报告之间有不一致，其中不少推荐已被后来的核对或用户决定取代。最容易带偏的说法列在两份报告各自的附录里。

## 阅读顺序

1. 第三轮评审 §1（结论）、§2（需要用户裁决的事：一个总的决定和五个具体决定）。
2. 第三轮评审 §3（其余八题的默认做法）、§9（阶段、依赖、验收与提交拆分）。

## 给实施者

- 当前状态：用户尚未批准实施。第三轮评审 §2 列出了需要用户先定的事；用户答复之前，不要按任何一份报告改候选、删能力或重写历史。
- 用户批准之后，范围和顺序以用户的答复为准；第三轮评审 §9 是建议的阶段划分和验收，§3 是其余各题的默认做法，§5 和上一版定稿 §6 是缺陷清单。
- 约束不变：隔离的工作副本或分支；不动主分支，不合入，不推送，不发布；只用 MuMu 和 Android Studio 模拟器（MuMu 不能建后台屏），运行结论写明"仅模拟器验证"；不新增 Android 内部接口，例外只有坐标输入的接收者判断，其它例外须用户明确同意；不新增自动重试、自动兜底、自动换通道。
- 没跑过的不写通过。模拟器结果不外推到真机；研究探针的结果不等于产品代码的结果。
- 报告里的源码位置和行号对应 `3f45af6`；标【推断】和【需设备】的结论先验证再依赖。
