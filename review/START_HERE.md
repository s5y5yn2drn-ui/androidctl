# 从这里开始

这是对 AndroidCtl 改进路线的评审材料。评审方只评审，不实施，不改提交历史。

评审到现在共五轮。前三轮评的是调研候选（产品 `3f45af6`，基线 `7d5be70`）和实施方的研究与建议；第四轮评的是实施方在其上继续做出的整轮候选（产品 `4235af9`，独立 docs `9b8c5bd`）；第五轮评的是实施方按第四轮决定继续做出的候选（产品 `cab84b8`，独立 docs `31bae00`）。

**当前状态：第五轮评审已交给用户，其中 17 道取舍等用户裁决。裁决作出之前，第四轮的决定仍然有效；第五轮报告里的推荐不是决定。**

## 以谁为准

1. 用户的明确指示。
2. `androidctl-r4-decisions.md` 里的决定。
3. 第三轮评审里用户确认过、又没有被上一条改动的授权范围、已决定事项和默认做法。
4. 第五轮评审的事实核查结果（§2、§4、§6）。它的推荐（§5）在用户裁决之前不是要求。
5. 第四轮评审的正文。
6. 前两轮定稿。
7. 工作记录。

工作记录写于不同时点，彼此之间、以及与各份报告之间有不一致。最容易带偏的说法列在各份报告的附录里。

## 阅读顺序

1. 第五轮评审 §1（结果）、§5（待裁决的取舍）、§4（发现）。
2. `androidctl-r4-decisions.md`：用户第四轮的决定、缺陷清单的去向、源码核实的结果。
3. 第四轮评审 §1（结论）、§4（缺陷清单及处理）、§7（下一步与各项的完成标准）。
4. 第四轮评审 §3（依据）、§5（四道待决题的结果）、§6（前几轮结论里应当改的）、§8（证据范围）按需查阅。
5. 授权范围与工作方式：第三轮评审 §2.1，其中被第四轮决定第 18 到 24 项改动的部分以后者为准。

## 给实施者

第五轮的讨论还没有结束。用户裁决之后，评审方会把结果写成新的决定文件，届时以它为准。在那之前：

- 要做什么、边界在哪，按 `androidctl-r4-decisions.md`；做到什么算完成，另见第四轮评审 §7。
- 第五轮评审 §1.5 列的事不依赖任何裁决，也不改任何已定的决定，可以先做。
- 决定文件里没有写到的取舍不要自行决定，列成带候选项的问题交给用户。
- 第四轮评审 §4 的缺陷清单可以直接核对；每条缺陷的去向见决定文件的第六节。

报告里的源码位置和行号：第五轮的报告对应 `cab84b8`，第四轮的两份文件对应 `4235af9`，前三轮的报告对应 `3f45af6`。标"推断"和"需设备"的结论先验证再依赖。
