# 从这里开始

这是对 AndroidCtl 改进路线的评审材料。评审方只评审，不实施，不改提交历史。

评审到现在共四轮。前三轮评的是调研候选（产品 `3f45af6`，基线 `7d5be70`）和实施方的研究与建议；第四轮评的是实施方在其上继续做出的整轮候选（产品 `4235af9`，独立 docs `9b8c5bd`）。

## 这里有什么

| 文件 | 作用 |
| --- | --- |
| `START_HERE.md` | 本页：以谁为准、阅读顺序 |
| `androidctl-r4-candidate-review-4235af9.md` | **第四轮评审，当前供讨论的主文件。** 对整轮候选的结论、需要用户定的四项事、缺陷清单、四道待决题的意见、建议的下一步 |
| `androidctl-r4-decisions.md` | 第四轮评审对应的决策清单：25 个待用户选择的决策点，每个带候选项、优缺点和推荐。用户选完之前都不生效 |
| `androidctl-r3-route-review-3f45af6.md` | 第三轮评审。其中的授权范围和已决定事项，在用户对第四轮评审作出新决定之前仍然有效 |
| `androidctl-candidate-route-review-3f45af6.md` | 前两轮定稿。各项做法的依据和验收标准仍可查阅；其中 18 处已被第三轮评审修订 |
| `sub-reports/01` … `46` | 评审过程的工作记录，只在需要追溯细节时查阅 |

## 以谁为准

1. 用户的明确指示。
2. 第三轮评审里用户已经确认的授权范围、已决定事项和默认做法。
3. 第四轮评审。它建议调整其中若干条（见该文 §2 和 §6），这些建议在用户确认之前不生效。
4. 前两轮定稿。
5. 工作记录。

工作记录写于不同时点，彼此之间、以及与各份报告之间有不一致。最容易带偏的说法列在各份报告的附录里。

## 阅读顺序

1. 第四轮评审 §1（结论）和 §2（需要用户定的事、默认做法）。
2. 第四轮评审 §4（缺陷清单）、§5（四道待决题）、§7（建议的下一步与验收）。
3. 第四轮评审 §3（依据）、§6（前几轮结论里应当改的）、§8（证据范围）按需查阅。
4. 当前有效的授权范围：第三轮评审 §2.1。

## 给实施者

第四轮评审是给用户讨论用的，其中的建议还没有成为要求。在用户作出新决定之前：

- 授权范围、已决定事项和默认做法仍按第三轮评审 §2 和 §3.2。
- 第四轮评审 §4 的缺陷清单可以直接核对；其中的修正方向是建议，标"见 §2.5"的几条要等用户确认。
- 第四轮评审对四道待决题的意见（§5）是给用户的参考，不代替用户的裁决。

报告里的源码位置和行号：第四轮评审对应 `4235af9`，前三轮的报告对应 `3f45af6`。标"推断"和"需设备"的结论先验证再依赖。
