# 从这里开始

这是对 AndroidCtl 改进路线的评审材料。评审对象是调研候选（产品 `3f45af6`，基线 `7d5be70`；独立 docs `e91212e`）和实施方三轮的研究、建议与模拟器实测。

评审方只评审，不实施，不改提交历史。当前的授权范围、已决定的事项和先验证再定的事项，都写在第三轮评审里。

## 以谁为准

1. 用户的明确指示。
2. 第三轮评审。
3. 上一版评审定稿（与第三轮评审不一致处，以第三轮评审为准）。
4. 工作记录。

工作记录写于不同时点，彼此之间、以及与两份报告之间有不一致，其中不少推荐已被后来的核对或用户决定取代。最容易带偏的说法列在两份报告各自的附录里。

## 给实施者

**授权范围**（第三轮评审 §2.1）

- 这一阶段仍属研究。允许在隔离分支上改产品代码并反复打磨，包括删命令、合并入口、改对外行为；做出来的可以再推翻重做。
- 在候选之上开新分支向前做。不动主分支，不合入，不推送，不发布，不改写现有 40 个提交的历史。
- 剩余未知用"做出来、跑真实任务"来回答，不再单开研究任务；要追加纯研究，先说明不同的结果会改变哪个决定。
- 第 0 阶段做完，带效率对照的数字向用户汇报一次；之后每阶段末用真实任务验收。
- 只用 MuMu 和 Android Studio 模拟器（MuMu 不能建后台屏），运行结论写明"仅模拟器验证"。

**做什么**

1. 按第三轮评审 §9 的阶段推进。第 0 阶段是无争议先行批次，含结果与退出码的合同、紧凑正文、`find` 和首页指引首版，做完做效率对照。
2. 已决定的事项按第三轮评审 §2.2–§2.5，默认做法按 §3.2；各项的"验收标准"就是完成定义。
3. 修掉第三轮评审 §5 和上一版定稿 §6 的缺陷。
4. 先验证再定的四项（第三轮评审 §3.1）：按"验证之前怎么做"推进，把要验证的结果报给用户。

**不要做什么**

1. 不把已定事项重新列为待决题。有带具体证据的反证可以提出，但不停工等待。
2. 不自行决定第三轮评审 §3.1 的四项。
3. 不新增 Android 内部接口，例外只有坐标输入的接收者判断；其它例外须用户明确同意。
4. 不新增自动重试、自动兜底、自动换通道。
5. 没跑过的不写通过。模拟器结果不外推到真机；研究探针的结果不等于产品代码的结果。

报告里的源码位置和行号对应 `3f45af6`；标【推断】和【需设备】的结论先验证再依赖。
