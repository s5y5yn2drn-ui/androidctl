# 从这里开始

这是对 AndroidCtl 改进路线的评审材料。评审方只评审，不实施，不改提交历史。

评审到现在共四轮。前三轮评的是调研候选（产品 `3f45af6`，基线 `7d5be70`）和实施方的研究与建议；第四轮评的是实施方在其上继续做出的整轮候选（产品 `4235af9`，独立 docs `9b8c5bd`）。

## 这里有什么

| 文件 | 作用 |
| --- | --- |
| `START_HERE.md` | 本页：以谁为准、阅读顺序 |
| `androidctl-r4-decisions.md` | **用户对第四轮评审各项取舍作出的决定，当前的主文件。** 另列出 13 处还在确认的问题 |
| `androidctl-r4-candidate-review-4235af9.md` | 第四轮评审：对整轮候选的结论、依据、缺陷清单。其中的建议以用户的决定为准；正文与决定的同步在 13 处问题确认之后进行 |
| `androidctl-r3-route-review-3f45af6.md` | 第三轮评审。没有被第四轮的决定改动的部分仍然有效 |
| `androidctl-candidate-route-review-3f45af6.md` | 前两轮定稿。各项做法的依据和验收标准仍可查阅；其中 18 处已被第三轮评审修订 |
| `sub-reports/01` … `46` | 评审过程的工作记录，只在需要追溯细节时查阅 |

## 以谁为准

1. 用户的明确指示。
2. `androidctl-r4-decisions.md` 里已经写明的决定。标"待确认"的 13 处还没有定。
3. 第三轮评审里用户确认过、又没有被上一条改动的授权范围、已决定事项和默认做法。
4. 第四轮评审的正文。
5. 前两轮定稿。
6. 工作记录。

工作记录写于不同时点，彼此之间、以及与各份报告之间有不一致。最容易带偏的说法列在各份报告的附录里。

## 阅读顺序

1. `androidctl-r4-decisions.md`：用户的决定、缺陷清单的去向、源码核实的结果、待确认的问题。
2. 第四轮评审 §1（结论）、§4（缺陷清单）。
3. 第四轮评审 §3（依据）、§6（前几轮结论里应当改的）、§8（证据范围）按需查阅。§2、§5、§7 是作出决定之前的建议，与决定不一致的地方以决定为准。
4. 授权范围与工作方式：第三轮评审 §2.1，其中被第四轮决定第 18 到 24 项改动的部分以后者为准。

## 给实施者

用户与评审方的讨论还没有结束，这份材料在讨论结束后才会转交。届时：

- 要做什么、做到什么算完成，按 `androidctl-r4-decisions.md`。
- 标"待确认"的地方不要自行取舍。
- 第四轮评审 §4 的缺陷清单可以直接核对；每条缺陷的去向见决定文件的第六节。

报告里的源码位置和行号：第四轮的两份文件对应 `4235af9`，前三轮的报告对应 `3f45af6`。标"推断"和"需设备"的结论先验证再依赖。
